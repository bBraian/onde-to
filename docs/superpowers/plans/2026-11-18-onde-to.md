# Onde Tô? — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fazer um jogo de navegador de adivinhar lugares a partir de fotos de rua do
Mapillary, com sala ao vivo (Clássico e Duelo em times) e treino solo.

**Architecture:** É um monorepo pnpm. `packages/shared` tem as regras puras
(pontuação, duelo, configurações, protocolo) e os JSON dos mapas. `apps/server` é um
servidor Node + Socket.IO que controla o jogo, com as salas guardadas em memória.
`apps/web` é o site React + Vite: o treino roda só no navegador, e a sala é um
cliente que mostra o `RoomView` enviado pelo servidor. `scripts/build-maps` gera os
JSON dos mapas a partir da API do Mapillary.

**Tech Stack:** Node 22, pnpm 10, TypeScript, React 19, Vite 8, React Router 8,
Socket.IO 4.8, MapillaryJS 4.1, MapLibre GL 6 + OpenFreeMap, Turf 7, Vitest 5,
Playwright 1.65, tsx.

**Spec:** `docs/superpowers/specs/2026-11-18-onde-to-design.md`. Quem executar este
plano deve ler a spec junto.

## Global Constraints

- Versões mínimas: `react ^19.3.1`, `react-dom ^19.3.1`, `vite ^8.3.8`,
  `@vitejs/plugin-react ^6.3.0`, `typescript ^7.0.2`, `vitest ^5.1.1`,
  `socket.io ^4.8.4`, `socket.io-client ^4.8.4`, `mapillary-js ^4.1.2`,
  `maplibre-gl ^6.19.0`, `react-router ^8.5.2`, `@playwright/test ^1.65.1`,
  `tsx ^4.23.15`, `@turf/random ^7.4.0`, `@turf/boolean-point-in-polygon ^7.4.0`,
  `@turf/area ^7.4.0`.
- Toda a interface fica em português do Brasil.
- Nada do GeoGuessr entra no projeto: nome, marca, logo, cores (roxo com amarelo),
  layout, textos ou arquivos.
- Créditos do Mapillary: o texto `© Mapillary` com link para
  `https://www.mapillary.com`, nunca para a página da imagem. O componente de
  créditos padrão do MapillaryJS fica desligado (`attribution: false`). O autor da
  foto só aparece no resultado da rodada.
- Todo tempo que decide o jogo é controlado pelo servidor e enviado como horário
  absoluto (epoch ms). O cliente só exibe a contagem.
- O servidor nunca envia `lat`/`lng` do local certo antes de a rodada entrar na fase
  `result`.
- Todo acesso a `localStorage` fica dentro de `try/catch`, e o jogo funciona mesmo
  sem ele.
- Pontuação: `round(5000 · e^(−10·d/D))`. Palpite a até 25 m vale 5000. O mapa Mundo
  usa `D = 14916.862` km.
- Variáveis de ambiente:
  - no site: `VITE_MAPILLARY_TOKEN`, `VITE_SERVER_URL`, `VITE_FAKE_VIEWER` (só em
    teste) e `VITE_ENABLE_TEST_MAP` (só em teste);
  - no servidor: `PORT`, `CORS_ORIGIN` e `ENABLE_TEST_MAP` (só em teste);
  - no script de mapas: `MAPILLARY_TOKEN`.
- Toda mensagem de commit termina com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Aba em segundo plano ou relógio do jogador adiantado.** A contagem tem que
   continuar certa. O cliente calcula o tempo restante a partir do `deadline` e de
   uma diferença de relógio (`serverNow − Date.now()`), não diminuindo um contador.
   Os testes ficam no Task 7 (`remainingSec` com diferença de relógio) e no Task 11
   (`clockOffset`).
2. **Jogador desconectado no meio da rodada.** Ele não pode travar a rodada: ela
   termina quando todos os *conectados* chutaram. O teste fica no Task 8.
3. **Imagem do Mapillary que não carrega** (apagada ou falha de rede). O visor mostra
   "Imagem indisponível". No treino, o local é trocado automaticamente. Na sala, o
   host tem o botão "Trocar local" (`round:reroll`), que sorteia outro ponto, zera os
   palpites e reinicia o tempo. Os testes ficam no Task 8 (`reroll`) e no Task 7
   (troca no treino).
4. **Entrada digitada com problema.** O apelido vazio, longo demais ou repetido e o
   código em minúsculas ou com espaços devem ser normalizados, nunca rejeitados sem
   motivo. Os testes ficam no Task 9.
5. **`localStorage` bloqueado** (aba anônima ou cookies bloqueados). O apelido e o
   token ficam na memória e o jogo segue funcionando, só que sem reconexão. O teste
   fica no Task 5.

**Interfaces:**
- Consumes: `GameMap`, `MapPoint`, `haversineKm`, `WORLD_SIZE_KM` e `mulberry32`, do
  `@onde-to/shared`.
- Produces:
  ```ts
  interface MlyImage { id: string; lat: number; lng: number; quality: number | null; creator: string | null }
  function searchPanos(bbox: [number, number, number, number], token: string): Promise<MlyImage[]>;
  function bboxAround(p: LatLng, halfDeg?: number): [number, number, number, number]; // padrão 0.045 → área 0.0081 < 0.01
  function pickImage(images: MlyImage[], minQuality: number, rng: () => number): MlyImage | null;
  function tooClose(p: LatLng, chosen: LatLng[], minKm: number): boolean;
  function mapSizeKm(points: LatLng[]): number; // haversine entre o canto SW e o NE do retângulo envolvente
  interface Region { name: string; target: number; sample(rng: () => number): LatLng }
  interface MapSpec { id: string; nome: string; regions: Region[]; minKm: number; fixedSizeKm?: number }
  function buildMap(spec: MapSpec, search: (bbox: [number, number, number, number]) => Promise<MlyImage[]>, rng: () => number, maxAttemptsPerPoint?: number): Promise<{ map: GameMap; report: Record<string, { target: number; got: number }> }>;
  ```
- `searchPanos` chama
  `GET https://graph.mapillary.com/images?access_token=…&bbox=minLng,minLat,maxLng,maxLat&is_pano=true&limit=200&fields=id,computed_geometry,geometry,quality_score,creator`.
  Usa `computed_geometry` e, se faltar, `geometry`. Repete até 3 vezes em caso de
  HTTP 429/5xx, com espera crescente.
- `pickImage` fica com as imagens que têm `quality ≥ minQuality` ou `quality` nula,
  e sorteia uma delas. Se não sobrar nenhuma, devolve `null`.
- Regiões (`regions.ts`), com as geometrias baixadas e guardadas em cache em
  `scripts/build-maps/.cache/`, que fica no `.gitignore`:
  - `brasil`: os estados, pela malha do IBGE
    (`https://servicodados.ibge.gov.br/api/v3/malhas/paises/BR?intrarregiao=UF&formato=application/vnd.geo+json&qualidade=minima`).
    O alvo de cada estado é proporcional à área (`@turf/area`), com mínimo de 8, e o
    total é 500. O ponto é sorteado dentro do polígono por amostragem com
    `@turf/random` e `boolean-point-in-polygon`. `minKm = 5`.
  - `capitais-br`: 15 pontos por capital, sorteados num raio de 10 km.
    `minKm = 0.5`.
  - `capitais-mundo`: as capitais nacionais do Natural Earth (`ne_110m_populated_places_simple.geojson`
    com `featurecla` igual a `"Admin-0 capital"`), 3 pontos por capital num raio de
    10 km. `minKm = 0.5`.
  - `mundo`: os países do Natural Earth (`ne_110m_admin_0_countries.geojson`). O alvo
    é proporcional à área, com teto de 40 por país, e o total é 1000.
    `fixedSizeKm = WORLD_SIZE_KM`. `minKm = 20`.
- `buildMap` tenta até `maxAttemptsPerPoint × target` vezes por região (padrão 20).
  `tamanhoKm` vem de `fixedSizeKm` quando existe e, senão, de `mapSizeKm`. O ponto
  guarda `autor` a partir de `creator.username`.
- `cli.ts` roda `pnpm build-maps [mapId…]`. Ele lê `MAPILLARY_TOKEN`, grava o JSON,
  mostra o relatório por região e avisa quando o total ficar abaixo do alvo. Termina
  com código 1 se o mapa tiver menos de 100 pontos.
